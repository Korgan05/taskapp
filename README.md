# 🚕 Дневник смен водителя (Driver Shift Logbook)

Мини-сервис для водителей такси и таксопарков: учёт ежедневных смен, расчёт суточной выручки, удержанной комиссии, чистого дохода «на руки» и разбивки по способам оплаты (наличные / карта) с защитой от дублирования поездок.

Проект разработан в соответствии с техническим заданием **arqa** с соблюдением дизайн-системы (фирменные цвета, термочек смены водителя, шрифты *Unbounded* и *Golos Text*).

---

## 📌 Что реализовано

1. **Серверный REST API (FastAPI + Pydantic v2)**:
   - `GET /api/summary?date=YYYY-MM-DD` — суточная сводка: количество поездок, выручка, комиссия, «на руки», разбивка наличные/карта.
   - `GET /api/trips?date=YYYY-MM-DD` — список всех поездок за выбранный день.
   - `GET /api/day?date=YYYY-MM-DD` — объединённый эндпоинт (сводка + список поездок) для мгновенного рендеринга.
   - `GET /api/dates` — список доступных календарных дат, за которые есть данные.
   - `POST /api/trips` — добавление поездки с полной валидацией и идемпотентной защитой от дублей.
   - Интерактивная документация Swagger/OpenAPI на `/docs`.

2. **Клиент (Mobile-First Web App / PWA)**:
   - Фирменный **«Чек смены» (термолента)** с перфорированным краем и анимацией печати — в точности как на витрине `arqa`.
   - **Удобная навигация по дням**:
     - Лента недели с индикаторами смен (синяя точка под днями, когда были поездки).
     - Быстрые переходы между сменами: `‹ Пред. смена` и `След. смена ›`.
     - Кнопка `Сегодня` для возврата в текущий день.
     - Клик по дате открывает нативный календарь (`showPicker`).
     - Поддержка горячих клавиш: `←` / `→` (день), `Shift + ←` / `→` (смена).
     - Поддержка свайпов влево/вправо на мобильных экранах.
     - Сохранение даты в URL-хэше (`#2026-10-01`) — выбор дня не сбрасывается при обновлении страницы.
   - Индикаторы выручки, комиссии (% от выручки), дохода «на руки» и прогресс-бар соотношения нал/безнал.
   - Модальное окно добавления поездки с кнопками быстрого выбора длительности (`+15м`, `+30м`), авторасчётом комиссии (15%) и кнопкой предзаполнения тестовыми данными.
   - Переключатель отображения: **Вид телефона** (440px мобильный контейнер водителя) / **Десктоп**.

3. **Валидация и защита от дублей**:
   - `amount > 0` (сумма строго больше 0).
   - `end > start` (окончание строго позже начала).
   - `commission >= 0` и `commission <= amount`.
   - Обязательный часовой пояс в ISO-метках времени (например, `+05:00`).
   - Идемпотентность:
     - Повторная отправка той же поездки возвращает `200 OK` с существующей записью и заголовком `Idempotent-Replay: true` (дубль не создаётся).
     - Попытка использовать уже занятый ID с другими данными отклоняется с `409 Conflict`.
     - Все проверки и запись защищены атомарной блокировкой в потокобезопасном хранилище.

4. **Тесты (Pytest — 30 тестов)**:
   - Расчёт сводки (включая эталонные цифры из ТЗ: 2 поездки, 3900 выручка, 585 комиссия, 3315 на руки, 1500 нал / 2400 карта).
   - Расчёт сводки за пустой день (все нули).
   - Расчёт границ суток по локальному часовому поясу водителя, а не UTC.
   - Защита от дублей: повтор с ID, повтор без ID, ретраи в других часовых поясах, параллельные запросы (race condition).
   - Валидация входных данных (`amount <= 0`, `end <= start`, `commission > amount`, неверный формат даты `422`).
   - Защита от перезаписи повреждённого JSON-файла.

## 🚀 Быстрый запуск

### 1. Установка зависимостей
Убедитесь, что установлен Python 3.10+:
```bash
pip install -r requirements.txt
```

### 2. Запуск сервера
```bash
python main.py
```
или через `uvicorn`:
```bash
uvicorn main:app --reload --port 8000
```

После запуска перейдите в браузере:
- 📱 **Веб-приложение водителя**: [http://127.0.0.1:8000](http://127.0.0.1:8000)
- ⚡ **Swagger API документация**: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

### 3. Запуск тестов
```bash
pytest -v
```

## 🤖 Как использовался ИИ (Разбор для анкеты)

### Где ИИ помог:
- Быстро сгенерировал первоначальную структуру FastAPI и базовые Pydantic-модели.
- Помог набросать заготовку для расчета CSS-маски термочека со срезанным зубчатым краем.
- Подготовил каркас юнит-тестов под `pytest`.

### Где ИИ ошибся и что было исправлено руками:
1. **Учёт часовых поясов (Timezone Shift `+05:00`)**:
   - *Проблема*: ИИ изначально парсил строки даты через `datetime.fromisoformat()` без учёта часового пояса и отрезал дату по UTC. Из-за этого поездка, начатая в `2026-10-01 02:00:00+05:00` (в Алматы), в UTC превращалась в `2026-09-30 21:00:00` и улетала в предыдущий день! На фронтенде при вызове `date.toISOString()` стрелка переключения дней в UTC+5 «залипала» на месте.
   - *Исправление*: На бэкенде день привязан к локальному времени старта (`trip.start.date()`). На фронтенде расчёт дат переведён на локальный календарь с полуднем `12:00:00` без UTC-сдвига.

2. **Защита от дублей и идемпотентность**:
   - *Проблема*: ИИ предложил проверять дубликаты только по полю `id`. Однако в мобильных сетях при нестабильном интернете водитель может отправить повторный запрос, когда клиентский ID ещё не зафиксирован или генерируется заново на клиенте. Кроме того, проверка и запись не были атомарными, что приводило к race condition при одновременных ретраях.
   - *Исправление*: Реализована семантическая дедупликация: совпадение ключевых полей возвращает существующую запись (`200 OK` с `Idempotent-Replay: true`), а коллизия ID с разными данными отклоняется (`409 Conflict`). Чтение, проверка и запись объединены в атомарную транзакцию с `threading.Lock`.

3. **Арифметика с плавающей точкой (IEEE 754)**:
   - *Проблема*: При вычитании комиссии (`3900 - 585`) в Python периодически всплывали хвосты вроде `3314.9999999999995`. В финансовых приложениях для водителей это недопустимо.
   - *Исправление*: Внедрено строгое банковское округление `round(..., 2)` на уровне бизнес-сервиса и сериализации моделей.

4. **Падение сервера на Windows (Console Unicode Error)**:
   - *Проблема*: ИИ добавил в консольный логгер эмодзи (`🚀`, `📖`), из-за чего в Windows PowerShell с локалью `cp1252` сервер падал при старте с `UnicodeEncodeError`.
   - *Исправление*: Логирование переведено на безопасный стандартный формат.
