# 🚕 Дневник смен водителя (Driver Shift Logbook)

Мини-сервис для водителей такси и таксопарков: учёт ежедневных смен, расчёт суточной выручки, удержанной комиссии, чистого дохода «на руки» и разбивки по способам оплаты (наличные / карта) с защитой от дублирования поездок.

Проект разработан в соответствии с техническим заданием **arqa** с соблюдением дизайн-системы (фирменные цвета, термочек смены водителя, шрифты *Unbounded* и *Golos Text*).

---

## 📌 Что реализовано

1. **Серверный REST API (FastAPI + Pydantic v2)**:
   - `GET /api/summary?date=YYYY-MM-DD` — суточная сводка: количество поездок, выручка, комиссия, «на руки», разбивка наличные/карта.
   - `GET /api/trips?date=YYYY-MM-DD` — список всех поездок за выбранный день.
   - `GET /api/day?date=YYYY-MM-DD` — объединённый эндпоинт (сводка + список поездок) для быстрого рендеринга клиента.
   - `GET /api/dates` — список доступных календарных дат, за которые есть данные.
   - `POST /api/trips` — добавление новой поездки с валидацией данных и защитой от дублей.
   - Интерактивная документация Swagger/OpenAPI на `/docs`.

2. **Клиент (Mobile-First Web App / PWA)**:
   - Фирменный **«Чек смены» (термолента)** с перфорированным краем и анимацией печати — в точности как на витрине `arqa`.
   - Переключение между днями (стрелки, календарь, быстрые чипсы доступных дат).
   - Индикаторы выручки, комиссии (% от выручки), дохода «на руки» и прогресс-бар соотношения нал/безнал.
   - Модальное окно добавления поездки с кнопками быстрого выбора длительности (`+15м`, `+30м`), авторасчётом комиссии (15%) и кнопкой предзаполнения тестовыми данными.
   - Переключатель отображения: **Вид телефона** (440px мобильный контейнер водителя) / **Десктоп**.

3. **Валидация и защита от дублей**:
   - `amount > 0` (сумма строго больше 0).
   - `end > start` (окончание строго позже начала).
   - `commission >= 0`.
   - Двухуровневая защита от дублей:
     1. По уникальному идентификатору `id` (если передан клиентом).
     2. По семантическому совпадению ключевых атрибутов поездки (`start`, `end`, `amount`, `payment`, `commission`).
   - При повторной отправке возвращается HTTP `409 Conflict`, а в интерфейсе водителя всплывает понятное уведомление.

4. **Тесты (Pytest)**:
   - 100% прохождение тестов на расчёт сводки (включая эталонные цифры из примера ТЗ: 2 поездки, 3900 выручка, 585 комиссия, 3315 на руки).
   - Проверка сводки за пустой день.
   - Тесты на отказ при дубликатах (по ID и по телу запроса).
   - Тесты валидации некорректных данных (`amount <= 0`, `end <= start`).

## 🚀 Быстрый запуск

### 1. Установка зависимостей
Убедитесь, что установлен Python 3.10+:
```bash
pip install -r requirements.txt
```

### 2. Запуск сервера
```bash
python main.py
```
или через `uvicorn`:
```bash
uvicorn main:app --reload --port 8000
```

После запуска перейдите в браузере:
- 📱 **Веб-приложение водителя**: [http://127.0.0.1:8000](http://127.0.0.1:8000)
- ⚡ **Swagger API документация**: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

### 3. Запуск тестов
```bash
pytest -v
```

## 🤖 Как использовался ИИ (Разбор для анкеты)

### Где ИИ помог:
- Быстро сгенерировал первоначальную структуру FastAPI и базовые Pydantic-модели.
- Помог набросать заготовку для расчета CSS-маски термочека со срезанным зубчатым краем.
- Подготовил скелет юнит-тестов под `pytest`.

### Где ИИ ошибся и что было исправлено руками:
1. **Учёт часовых поясов (Timezone Shift `+05:00`)**:
   - *Проблема*: ИИ изначально парсил строки даты через `datetime.fromisoformat()` без учёта часового пояса и отрезал дату по UTC (`.date()`). Из-за этого поездка, начатая в `2026-10-01 02:00:00+05:00` (в Алматы), в UTC превращалась в `2026-09-30 21:00:00` и улетала в предыдущий день!
   - *Исправление*: Логика группировки и сопоставления была переписана с сохранением локального смещения поездки (`trip.start.strftime("%Y-%m-%d")`), гарантируя точный расчёт смен для водителей в Казахстане.

2. **Слабая защита от дублей**:
   - *Проблема*: ИИ предложил проверять дубликаты только по полю `id`. Однако в мобильных сетях при нестабильном интернете водитель может отправить повторный запрос, когда клиентский ID ещё не зафиксирован или генерируется заново на клиенте.
   - *Исправление*: Реализована двухфакторная дедупликация: сначала по явному `id`, а затем по семантическому кортежу `(start, end, amount, payment, commission)`. Повторный запрос возвращает корректный HTTP `409 Conflict` и не дублирует финансовые показатели.

3. **Арифметика с плавающей точкой (IEEE 754)**:
   - *Проблема*: При вычитании комиссии (`3900 - 585`) в Python периодически всплывали хвосты вроде `3314.9999999999995`. В финансовых приложениях для водителей это недопустимо.
   - *Исправление*: Внедрено строгое банковское округление `round(..., 2)` на уровне бизнес-сервиса и сериализации моделей.

4. **Падение сервера на Windows (Console Unicode Error)**:
   - *Проблема*: ИИ добавил в консольный логгер эмодзи (`🚀`, `📖`), из-за чего в Windows PowerShell с локалью `cp1252` сервер падал при старте с `UnicodeEncodeError`.
   - *Исправление*: Логирование переведено на безопасный стандартный формат.
