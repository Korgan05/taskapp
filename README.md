# 🚕 Дневник смен водителя (Driver Shift Logbook)

> 🚀 **Онлайн демо-стенд (Live App)**: [https://arqa-taskapp.onrender.com](https://arqa-taskapp.onrender.com)  
> ⚡ **Swagger API Документация**: [https://arqa-taskapp.onrender.com/docs](https://arqa-taskapp.onrender.com/docs)

Мини-сервис для водителей такси и таксопарков: учёт ежедневных смен, расчёт суточной выручки, удержанной комиссии сервиса, чистого дохода «на руки» и разбивки по способам оплаты (наличные / карта) с надёжной защитой от дублирования поездок.

Проект разработан в соответствии с техническим заданием **arqa** с соблюдением дизайн-системы (фирменная тёмная палитра mobility, шрифты *Unbounded*, *Inter* и *JetBrains Mono*).

## 📌 Что реализовано

### 1. Серверный REST API (FastAPI + Pydantic v2):
- `GET /api/summary?date=YYYY-MM-DD` — суточная сводка: количество поездок, выручка, комиссия, «на руки», разбивка наличные/карта.
- `GET /api/trips?date=YYYY-MM-DD` — список всех поездок за выбранный день.
- `GET /api/day?date=YYYY-MM-DD` — объединённый эндпоинт (сводка + список поездок) для мгновенного рендеринга страницы.
- `GET /api/dates` — список доступных календарных дат, за которые есть данные смен.
- `POST /api/trips` — добавление поездки с валидацией и идемпотентной защитой от дублей.
- Интерактивная документация Swagger/OpenAPI на `/docs`.

### 2. Клиент (Mobile-First Web Terminal):
- **Аналитическая карточка смены (Income Hero)**: крупный фокус на ключевом показателе водителя — чистый доход «на руки» после вычета комиссии, общая выручка смены, удержанная комиссия сервиса и интерактивный прогресс-бар соотношения безналичных (карта) и наличных оплат.
- **Фирменный «🧾 Чек смены»**: интерактивное модальное окно с детальной термолентой смены (выручка, комиссия, чистая выплата, список заказов, штрихкод и кнопка печати).
- **Единая навигация по дням и сменам**:
  - Компактный чип выбора даты `[ 📅 01 октября 2026 ▾ ]` для быстрого вызова календаря без лишнего визуального шума.
  - Недельная лента с днями недели (Пн–Вс) и зелёными точками-индикаторами смен.
  - Навигационные стрелки `‹` и `›` для переключения дней без дублирования кнопок.
  - Быстрый переход к текущей дате в календаре (`Сегодня`).
  - Сохранение выбранного дня в URL-хэше (`#2026-10-01`) — смена не сбрасывается при перезагрузке страницы.
  - Поддержка клавиатурной навигации стрелками `←` / `→` и клавиши `Escape` для закрытия окон.
- **Интерактивный календарь на месяц**:
  - Полноценное модальное окно календаря с переключением месяцев (`‹` / `›`).
  - Маркировка дней с поездками зелёными индикаторами и мгновенный переход к любой смене в один клик.
- **Детализированный список поездок (Progressive Disclosure)**:
  - Стабильные карточки поездок без лишнего визуального дёрганья.
  - Клик по карточке раскрывает подробный финансовый расчёт: чистая выплата за заказ, тариф, комиссия сервиса с процентом, время и длительность в минутах, способ оплаты и ID.
- **Модальное окно добавления поездки**:
  - Быстрый выбор длительности (`+15м`, `+30м`), авторасчёт комиссии (15%), сегментированный выбор способа оплаты.
  - Защита от спама уведомлений (дедупликация тостов) и автоматическая блокировка фонового скролла при открытых модалках (`body.modal-open`).
- **Тёмная и светлая тема**: сохранение выбора водителя в `localStorage`.

### 3. Валидация и защита от дублей:
- `amount > 0` (сумма строго больше 0).
- `end > start` (окончание строго позже начала).
- `commission >= 0` и `commission <= amount`.
- Обязательный часовой пояс в ISO-метках времени (например, `+05:00`).
- Приведение любого входного ISO-офсета (включая UTC/`Z`) к локальному часовому поясу смены водителя (`UTC+05:00`, Алматы) перед определением календарного дня.
- Идемпотентность:
  - Поддержка стандартного HTTP-заголовка `Idempotency-Key` (IETF draft / Stripe-style).
  - Повторная отправка той же поездки возвращает `200 OK` с существующей записью и заголовком `Idempotent-Replay: true` (дубль не создаётся).
  - Попытка использовать уже занятый ID с другими данными отклоняется с кодом `409 Conflict`.
  - Все проверки и запись защищены атомарной блокировкой `threading.Lock` в потокобезопасном хранилище.

### 4. Тесты (Pytest — 32 теста):
- Расчёт сводки (включая эталонные цифры из ТЗ: 2 поездки, 3900 выручка, 585 комиссия, 3315 на руки, 1500 нал / 2400 карта).
- Расчёт сводки за пустой день (все нули).
- Расчёт границ суток по локальному часовому поясу водителя (+05:00).
- Корректная конвертация ночных поездок в UTC (`...Z`) к алматинскому дню смены.
- Защита от дублей: повтор с ID, повтор без ID, ретраи в других часовых поясах, поддержка заголовка `Idempotency-Key`, параллельные запросы (race condition).
- Валидация входных данных (`amount <= 0`, `end <= start`, `commission > amount`, неверный формат даты `422`).
- Защита от перезаписи повреждённого JSON-файла.

## 🚀 Быстрый запуск

### 1. Установка зависимостей
Убедитесь, что установлен Python 3.10+:
```bash
pip install -r requirements.txt
```

### 2. Запуск сервера
```bash
python main.py
```
или через `uvicorn`:
```bash
uvicorn main:app --reload --port 8000
```

После запуска перейдите в браузере:
- 📱 **Веб-приложение водителя**: [http://127.0.0.1:8000](http://127.0.0.1:8000)
- ⚡ **Swagger API документация**: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

### 3. Запуск тестов
```bash
pytest -v
```

### 4. Запуск в Docker
Собрать и запустить контейнер:
```bash
docker build -t arqa-taskapp .
docker run -d -p 8000:8000 --name taskapp arqa-taskapp
```
Приложение сразу доступно на [http://localhost:8000](http://localhost:8000).

## 🤖 Как использовался ИИ (Разбор для анкеты)

### Где ИИ помог:
- Быстро сгенерировал первоначальную структуру FastAPI и базовые Pydantic-модели.
- Помог быстро набросать заготовку сетки интерактивного календаря.
- Подготовил каркас начальных юнит-тестов под `pytest`.

### Где ИИ ошибся и что было исправлено руками:
1. **Учёт часовых поясов (Timezone Shift `+05:00` Алматы)**:
   - *Проблема*: ИИ изначально парсил строки даты через `trip.start.date()` без приведения к локальному часовому поясу водителя. Из-за этого ночная алматинская поездка, пришедшая от сторонней системы в формате UTC (`2026-09-30T21:00:00Z`, что соответствует `2026-10-01 02:00:00+05:00`), ошибочно относилась к 30 сентября вместо 1 октября.
   - *Исправление*: На бэкенде внедрено строгое приведение времени к часовому поясу смены через `trip.start.astimezone(DRIVER_TZ).date()`, а в набор тестов добавлен специальный кейс `test_utc_normalized_trips_converted_to_driver_timezone`. На фронтенде расчёт дат переведён на локальный календарь с полуднем `12:00:00` без искажения UTC.

2. **Защита от дублей и идемпотентность**:
   - *Проблема*: ИИ предложил проверять дубликаты только по полю `id`. Однако в мобильных сетях при нестабильном интернете клиент может отправить повторный запрос с перегенерированным ID или без ID. Кроме того, проверка и запись не были атомарными, что создавало race condition при одновременных ретраях.
   - *Исправление*: Реализована двухуровневая дедупликация: совпадение по ID или по семантической сигнатуре полей возвращает существующую запись (`200 OK` с `Idempotent-Replay: true`), а коллизия ID с разными данными отклоняется (`409 Conflict`). Чтение, проверка и запись объединены в атомарную транзакцию с `threading.Lock`.

3. **Финансовая арифметика и отображение копеек**:
   - *Проблема*: При вычитании комиссии (`3900 - 585`) в Python периодически всплывали хвосты `3314.9999999999995`, а на фронтенде `Intl.NumberFormat` округлял всё до целых (`maximumFractionDigits: 0`), скрывая тиыны/копейки.
   - *Исправление*: Внедрено строгое округление `round(..., 2)` на уровне бизнес-логики и моделей, а на клиенте настроен вывод до 2 знаков (`maximumFractionDigits: 2`).

4. **UX-детали, скролл и спам уведомлений**:
   - *Проблема*: При многократном клике на заполнение примера ИИ бесконечно плодил всплывающие тосты стопкой, а при открытии модального окна фон страницы продолжал скроллиться колесиком мыши.
   - *Исправление*: Разработана дедупликация тостов с визуальным импульсом (`toast-pulse`) и блокировка скролла фона `updateScrollLock()` на время открытия модалок.
